更新日期：2026-10-17

## 1. 目标与默认路线

开发一个独立安卓客户端：填写 MeBox 后端地址、用户名和密码即可登录，日常使用自动恢复会话，提供比移动网页更可控的播放、阅读、听书和网络恢复体验。

默认路线：保留 MeBox 的 Go 后端与网页；增量补齐移动端契约；使用 Kotlin、Jetpack Compose 与 Media3 开发原生安卓客户端。先交付连接登录与一个完整业务模块，再逐渐扩展。

本目录是后续开发依据，不表示所有建议已经获得最终确认，更不表示文中新增接口、文件和测试已经存在。当前不稳定现象尚未复现，不能据此断言故障根因。

## 3. 两个项目的边界

- 安卓仓库：`D:\project\MeBox-APP`。App、安卓测试和本规划目录属于这里。
- 后端仓库：`D:\project\MeBox`。Go API、数据库迁移、现有网页兼容调整属于那里。
- 本轮后端工作在独立分支 `feature/android-mobile-api`；安卓改动尚未提交。
- 文档中的 `MeBox/...` 路径相对后端仓库；`MeBox-APP/...` 路径相对安卓仓库。
- 标记为“现有”的路径来自源码检查；标记为“拟新增”的路径是后续建议，不是现有实现。
- 修改两边代码时分别管理提交，记录适配的后端与 App 版本，避免只更新一端。

## 4. 推荐交付顺序

1. M0：复现实际问题、确认首个业务模块、锁定开发环境与接口基线。
2. M1：服务器识别、设备会话和基础契约。
3. M2：安卓工程、连接、登录和持久会话；可以独立测试账号接入。
4. M3：影视浏览和原生播放；默认作为首个业务版本。
5. M4：阅读、漫画和后台听书；若主要痛点在阅读，可在 M0 决定与 M3 交换顺序。
6. M5：离线内容与同步增强；影视离线下载另行确认范围。
7. M6：集中回归、发布和升级维护。

M3 与 M4 不要求一次全部完成；各自内部按任务顺序验收。正式对外发布前仍需完成 M6 的对应发布门槛。

## 5. 后续开发的工作规则

- 每次只领取 04 中一个任务；依赖未满足时先完成依赖。
- 开始前复核源码、运行配置和工具链；规划中的参考路径不得代替实际检查。
- 先写针对行为的失败测试，再实现最小改动，再运行回归。
- 状态明确区分：未开始、进行中、阻塞、已验证。只有验收通过才能勾选任务。
- 证据记录在对应任务下：实际命令、结果、设备/环境、提交标识、已知限制。
- 修改接口、数据结构、范围或默认方案时同步更新 02、03、04 和 06 的相关部分。
- 规划文件只保存在当前仓库；不自动复制到后端仓库，不自动提交或推送 Git。
- 密码、访问令牌、刷新令牌、网盘凭据、可直接访问私有资源的签名 URL 均不进入文档和测试样本。

## 6. 当前默认与确认边界

- 默认平台：Android 手机和平板；电视端和 iOS 不在首版范围。
- 默认技术：原生 Kotlin + Compose + Media3，推荐最低 Android 8.0 / API 26。
- 默认功能顺序：影视优先，随后阅读；M0 允许根据实际痛点调整。
- 首版只启用一个服务器配置，但本地数据从一开始按服务器和账号隔离。
- 公网默认 HTTPS；局域网 HTTP 由用户显式确认风险后允许。
- 首版支持域名/IP/端口与根路径部署；反代子路径是独立兼容项，未验收前明确提示不支持。
- 尚未承诺固定开发周期；M0 完成后依据样本、范围和投入估算。
