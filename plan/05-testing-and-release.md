# 05 测试、验收与发布规范

日期：2026-10-17  
状态：验收方案，以下用例均不代表已经通过。  
关联：[开发任务](04-development-roadmap.md)、[后端契约](02-backend-evolution.md)、[App 设计](03-android-app-design.md)。

## 1. 证据和通过规则

- 每个发布功能都有自动化测试或真实设备证据；“代码已写”“界面存在”“命令启动”不等于验收通过。
- 记录：任务 ID、版本/提交、时间、环境、样本类型、步骤、实际结果、期望结果、脱敏请求 ID 和限制。
- 测试结果区分通过、失败、未执行、环境阻塞；被 Skip 的 PostgreSQL 或设备测试不是通过。
- 自动测试使用隔离测试用户、临时目录和测试数据库；不直接写入生产 MeBox 数据。
- 测试媒体与书籍需有使用权限；不要把个人资源、账号、Cookie 或签名链接提交到仓库。
- 当前只新增规划文件，没有运行下面的业务测试，也没有验证 Android 构建环境。

## 2. 自动化测试层次

### 2.1 后端单元与契约

工作目录：`D:\project\MeBox`。

- 定向 handler/service/repository/database/middleware 测试覆盖参数、权限、状态和错误码。
- OpenAPI 示例验证字段名、时间单位、空集合、状态码和能力开关；成功与失败响应都检查。
- 全量回归：`go test ./...`。
- PostgreSQL 集成测试使用现有 `MEBOX_TEST_POSTGRES_DSN` 环境变量；通过安全环境配置注入测试 DSN，不把连接凭据写进文档/脚本。
- 执行 `go test ./internal/database -count=1 -v` 时检查是否实际运行 PostgreSQL 子测试；如被跳过，在报告中标为未覆盖。
- ffmpeg 行为按有工具/无工具/不可执行/转码失败分别验证；没有 ffmpeg 时只能验证缺失降级，不能证明转码正常。

### 2.2 网页和第三方兼容

- 构建：`npm --prefix web run build`。
- 对现有 authRefresh、hlsPlayback、playerPageModel、阅读进度与媒体分组等测试运行 Vitest；先验证已安装的测试工具，命令不得触发临时下载未锁版本的依赖。
- 旧网页实际执行登录、刷新、媒体播放、续播、阅读保存和退出。
- 已承诺支持的第三方 Emby 客户端实际执行登录、浏览、播放和进度同步，不能只根据 README 声明兼容。

### 2.3 安卓 JVM 单元测试

工作目录：`D:\project\MeBox-APP`，要求 M2-01 后存在 Gradle Wrapper。

- `.\gradlew.bat :app:testDebugUnitTest`。
- MockWebServer 覆盖请求和重定向，不依赖外网实时服务。
- 纯状态测试覆盖地址、错误映射、刷新并发、候选恢复、绝对位置和同步策略。
- Room/协程测试覆盖取消、事务、队列、迁移、时钟和任务代次；需要设备的数据库场景移到仪器测试。

### 2.4 安卓仪器与真实设备

- `.\gradlew.bat :app:connectedDebugAndroidTest`。
- `.\gradlew.bat :app:lintDebug :app:assembleDebug`。
- Compose 测试覆盖登录/错误/导航、配置变化和可访问性标签。
- Keystore、媒体服务、播放器和 WebView 权限隔离需要设备验证；模拟结果不能代替所有真实解码能力。
- 至少覆盖最低支持 Android、一个中间版本和目标平台版本；若测试设备不足，发布范围必须说明限制。

## 3. 接入与认证用例

### A-01 地址与 TLS

输入域名、IPv4、括号 IPv6、端口、尾斜线、无 scheme、子路径、含内嵌凭证/查询/片段、无效证书。

期望：规范化结果可预测；拒绝危险地址；HTTPS 不静默降级；局域网 HTTP 需明确确认；未支持子路径时说明原因。

### A-02 登录、权限与账号状态

正确/错误密码，账号禁用/到期，普通用户/管理员，受限媒体库，播放配置 PIN。

期望：返回正确错误分类；UI 和服务端授权一致；绕过页面直接请求仍被拒绝；不给账号不存在等内部细节增加无必要泄露。

### A-03 刷新并发

同账号制造 20 个并发访问令牌过期请求。

期望：客户端只启动一个刷新任务；服务端轮换结果一致；原请求最多重放一次，不形成刷新风暴。

### A-04 网络与重启恢复

断网、超时、DNS、502/503、普通 App 冷启动、普通服务重启、刷新成功但响应丢失。

期望：临时故障保留本地会话；有效持久刷新令牌在常规重启后可用；响应丢失再遇服务重启的已知边界给明确重新认证提示，不无限等待。

### A-05 设备与退出

单设备踢出、kick-all、改密、退出时远端不可达、退出后旧刷新响应晚到。

期望：新 sid 令牌对旧 API 的绕过也失败；其他未被撤销设备正常；本地退出不被迟到响应复活。

## 4. 播放样本与验收

### P-01 样本分类

至少为实际承诺支持的类别准备代表样本：

- 本地 MP4/H.264/AAC，作为基本直接播放。
- MKV 与手机支持/不支持的 HEVC；多声道音频作为单独能力验证。
- 本地转码、片中 seek、长片和已完成 HLS 输出。
- STRM、115 链接与云端 HLS；链接过期和上游限流。
- 远程 Emby 可播放条目及剧集容器。
- 外挂 SRT/VTT；ASS、内嵌/图片字幕按发布承诺单独验证。

报告要写容器、视频编码、音频编码、字幕、分辨率、设备与所用候选；不能用“MP4 播放通过”推断所有视频通过。

### P-02 起播、seek 与候选切换

从头播放、续播、远处 seek、快速连续 seek、切清晰度/字幕/音轨、候选过期。

期望：绝对位置保留，转码 timeline_offset_ms 正确；不回到零、不写入错误时长；失败回退有上限。

### P-03 多设备隔离

两台设备或两个用户同时播放同一媒体，但采用不同起点/质量；一端退出或拖动。

期望：另一端不被停止、输出目录不互相覆盖；同用户跨设备续播冲突遵循会话顺序而不是请求到达时间。

### P-04 进度与乱序

重复/乱序事件、旧会话晚到、客户端时钟差异、主动回看、暂停/切片/退出、网络恢复和孤立本地进度。

期望：最近合法操作被保存，旧事件不能覆盖新状态；不采用位置最大值策略；未知时长不覆盖正确已知时长。

### P-05 生命周期与后台音频

旋转、回桌面、锁屏、耳机控制、耳机拔出、来电、通知控制、省电限制、系统回收、服务重启。

期望：视频首版退后台暂停；明确启用的音频由媒体服务播放；用户已暂停后不擅自恢复；异常退出后以最后本地已保存位置恢复。

## 5. 阅读与离线验收

### R-01 文本与跨设备位置

TXT/EPUB 服务端解析结果、网络正文、空目录、单章错误、段落/字符位置、改变字号/行距、不同屏幕。

期望：恢复到可解释的正文位置；旧页码只能恢复章节时如实说明；服务端解析失败不会被误报成需要重登。

### R-02 漫画与听书

漫画大图/缺图/解密代理、图片顺序变化、有声书普通音频/HLS/转码、倍速/定时/下一章。

期望：类型化位置正确，图内比例合法；图片内存与预取有上限；音频毫秒精度与旧秒字段适配一致。

### R-03 网页/App 交替与版本冲突

网页保存进度后 App 用旧 base_revision 写入；离线期间另一设备继续阅读；目录更新或换源。

期望：冲突可见、双方位置保留；旧协议写入也改变 revision；重映射失败安全回到章节，不误用其他章字符偏移。

### R-04 特殊页面

待办登录/验证码/评论、回传 DOM、代理 XHR、取消、超时、切账号、导航到外站。

期望：等待能解除，旧待办不能提交到新账号；外站没有 MeBox token/高权限桥；不承诺未经验证的 Cookie 登录链路。

### R-05 持久离线缓存

批量最多 64 章、部分失败、下载暂停/取消、系统回收、资源签名失效、飞行模式、容量不足、退出清理。

期望：完成下载的内容确实有本地字节；部分错误不吞掉全部结果；固定离线内容不被普通缓存 LRU 随意删掉。

### R-06 文本朗读（仅发布该功能时）

语音引擎/声音包缺失、段落暂停恢复、切章、音频焦点、定时、与视频/有声书互斥。

期望：失败不影响文本阅读，位置使用文本锚点而不是伪造音频秒数。

## 6. 数据与安全验收

- S-01：两个服务器同用户名、同资源 ID，以及同服务器不同账号不串 token、缓存、队列与历史。
- S-02：权限不同的播放配置不会通过旧缓存看到不该显示的内容；切换配置刷新/隔离相关数据。
- S-03：跨来源 302、第三方图片、媒体分片、WebView 外站不收到 MeBox Authorization/refresh token。
- S-04：数据库/日志/异常/诊断导出/系统备份不包含密码、token、Cookie、PIN 或完整私有签名 URL。
- S-05：新协议签名资源的到期、撤销、越资源/越用户访问均按设计拒绝；携 sid 的令牌走旧 API 也不能绕过会话撤销。既有无时效 HMAC 链接单独记录兼容限制，不伪装为已经可以逐设备即时撤销。
- S-06：SQLite/PostgreSQL 从旧库迁移、重复迁移、App Room 升级均通过；未同步位置不得被普通清缓存删除。
- S-07：Keystore 不可用、密钥被清除、App 备份恢复后可安全重新认证，不进入崩溃循环。

## 7. 性能和稳定性记录

先在 M0 记录同设备/网络/资源下的网页基线，再比较 App：登录耗时、首屏时间、起播时间、seek 恢复时间、缓冲次数、后台音频中断与进度恢复误差。

记录样本量、失败次数、网络类型、设备和服务负载；未实测不填写虚构均值/成功率。发布目标根据首版样本冻结，不以统一起播秒数覆盖网盘唤醒或远程转码等待。

设计默认值为每 5 秒本地保存、每 15 秒在线同步；实际验收需模拟崩溃/断网并记录丢失窗口，不承诺零丢失。

## 8. 发布阻断与版本管理

以下问题阻断发布：越权、凭证泄露、串账号数据、退出被复活、常规进度静默丢失、不同播放会话互相停止、无限刷新/重试、数据库破坏性迁移或已承诺能力无法基本使用。

可以记录为已知限制的内容必须明确：未承诺格式、高级字幕特效、反代子路径、自签名证书、部分书源、已披露的极端轮换恢复窗口。基础功能故障不能用已知限制清单掩盖。

发布版本关联 App versionCode/versionName、后端最低版本/API 能力、签名、构建提交和验收记录。签名密钥只由安全环境注入，不进入 Git。

对外发布前覆盖安装验证 Room 和凭证迁移；旧后端/新 App、新后端/旧网页分别验证。回滚先确认数据格式兼容，必要时恢复备份；恢复验证也需要记录。

## 9. 完成标准

一个任务的“已验证”需要同时满足：对应行为、失败路径、权限边界、自动化测试/设备证据、文档和已知限制均已覆盖。

一个业务版本的“可发布”需要：相关任务通过、M6 对应检查通过、正式签名产物可安装、兼容范围清楚、回滚/恢复方案可执行。没有实现的后续模块不阻塞当前发布，但其入口和能力开关必须关闭。
