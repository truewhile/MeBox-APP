# 03 安卓客户端设计

日期：2026-10-17  
状态：原生 Android 默认设计；当前尚无工程实现。  
仓库根目录：`D:\project\MeBox-APP`。

## 1. 技术与工程约束

- Kotlin + Jetpack Compose；单 Activity，Compose Navigation 管理页面。
- ViewModel + StateFlow 表达页面状态，协程处理可取消异步任务。
- OkHttp + Retrofit 处理 HTTP；JSON 使用 kotlinx.serialization；Coil 处理图片。
- Media3 ExoPlayer 负责视频/音频，MediaSessionService 负责后台媒体控制。
- Room 保存本地进度、内容缓存索引和待同步任务；DataStore 保存普通配置。
- 令牌使用 Android Keystore 保护的加密文件；DataStore 不直接明文保存认证凭证。
- WorkManager 用于可以延期的同步与缓存工作，不维持实时播放或永久连接。
- 单一 `:app` Gradle 模块起步，按功能分包；手动 AppContainer 注入依赖，规模增加再评估依赖注入框架和模块拆分。
- 推荐 minSdk 26。compileSdk、targetSdk、JDK、AGP、Gradle 和依赖版本在 M0 按已验证的稳定兼容组合锁定，禁止使用动态 `+` 版本。
- 包名暂定 `app.mebox.android`；M0 确认后创建工程，首次分发签名 APK 后不随意变更。
- 不在本轮规划阶段生成工程；真正构建成功后才能宣称 App 可运行。

## 2. 建议目录与职责

以下均为拟新增结构，路径以 `app/src/main/java/app/mebox/android/` 为基础。

- `MeBoxApplication.kt`：应用初始化；`MainActivity.kt`：窗口与导航宿主。
- `di/AppContainer.kt`：依赖组装，避免在 Composable 中创建网络或数据库。
- `core/model/`：实例身份、账号分区、统一业务错误与共享值类型。
- `core/network/ServerAddress.kt`：地址规范化与来源判断。
- `core/network/MeBoxApi.kt`：既有端点定义；`MobileApi.kt`：v1 端点定义。
- `core/network/ApiErrorMapper.kt`：旧/new 响应映射，不将业务错误直接散落到页面。
- `core/network/AuthCoordinator.kt`：单次刷新、失败分类和认证代次校验。
- `core/network/MediaHttpClient.kt`：受限媒体请求与跨来源重定向策略。
- `core/security/CredentialStore.kt`、`KeystoreCredentialStore.kt`：凭证接口与原子加密保存。
- `core/database/MeBoxDatabase.kt`、`entity/`、`dao/`：Room 数据库与迁移。
- `core/sync/ProgressOutbox.kt`、`ProgressSyncWorker.kt`：待同步事件与恢复。
- `core/ui/`：主题、加载/错误/离线视图与可访问性基础组件。
- `navigation/MeBoxNavHost.kt`：登录、主页面和全屏播放器的导航。
- `feature/connection/`：服务器地址、测试连接和账号输入。
- `feature/home/`：继续观看/阅读和最近内容。
- `feature/library/`：媒体库、筛选、搜索、详情和选集。
- `feature/player/`：播放控制器、播放状态、视频页面与轨道选择。
- `feature/reader/`：书架、章节、文本布局、漫画和阅读设置。
- `feature/audio/`：有声书、文本朗读控制、计时与音频状态。
- `feature/account/`：账号、服务器、设备、退出、缓存和诊断。
- `service/MeBoxMediaSessionService.kt`：后台音频与媒体会话。

测试同名镜像放在 `app/src/test/...` 和 `app/src/androidTest/...`；页面模型、网络协调和存储分别测试，不依赖真实 NAS 才能跑单元测试。

## 3. 主要界面与导航

### 3.1 首次连接

字段：服务器地址、用户名、密码。高级设置单独展开，首版不要求用户理解接口路径或令牌。

操作顺序：规范化地址 → 测试服务 → 检查版本/能力 → 提交登录 → 安全保存令牌 → 载入权限/播放配置 → 首页。

- 支持明确带 scheme 的域名、IPv4、带括号 IPv6、端口和尾斜线处理。
- 无 scheme 时默认 HTTPS；失败不静默降到 HTTP。
- 拒绝 URL 内嵌用户名密码、查询参数、片段、非 HTTP(S) scheme。
- 根路径部署为首版支持范围；输入子路径明确提示兼容限制，不自动删除。
- 局域网 HTTP 必须确认风险。网络栈在发送任何凭证前检查该配置；Manifest 的 cleartext 兼容设置不能替代应用层来源限制。
- 不能把连接超时、证书错误、版本不兼容、密码错误都显示成“网络错误”。

### 3.2 主导航

最终四入口：首页、影视、阅读、我的。

- 首页：继续观看/阅读、最近添加、账号与连接状态；模块未完成时不显示可点击的空入口。
- 影视：媒体库、分页、筛选、搜索、详情、剧集/版本选择。
- 阅读：书架、分组、书籍搜索、目录、原生正文/漫画与听书。
- 我的：服务器、账号、播放配置、设备、缓存、诊断、关于和退出。

详情页应区分加载、空内容、权限不足、网络不可用和资源不存在。列表滚动位置按服务器/账号/列表条件恢复。

### 3.3 播放与阅读界面

视频全屏播放提供播放/暂停、拖动、倍速、音轨、字幕、清晰度、选集和恢复提示。画中画和弹幕后续独立交付。

阅读界面提供字号、行距、主题、目录、章节切换和阅读位置。复杂分页效果不作为正文闭环的前置条件；先实现稳定纵向阅读，再做翻页。

手机和平板使用自适应列数与布局，不把桌面网页缩放成手机。支持系统字体放大、屏幕阅读器标签和触控目标；颜色之外也能识别错误与选中状态。

## 4. 状态模型与认证恢复

### 4.1 账号状态

统一状态：Unconfigured、TestingConnection、SignedOut、SigningIn、Authenticated、TemporarilyUnavailable、ReauthenticationRequired。

只有收到明确的账号禁用/到期、会话撤销或无效刷新凭证才进入重新认证。超时、TLS、DNS、502/503 和断网不会自动删除安全存储。

### 4.2 单次刷新与写入顺序

1. 所有请求捕获当前 server_id、user_id 和认证 generation。
2. 访问令牌即将到期或返回 TOKEN_EXPIRED 时，经 AuthCoordinator 只启动一次刷新，其余请求等待。
3. 刷新成功先原子保存完整令牌对和 generation，再开放等待请求。
4. 每个原请求最多重放一次；第二次认证失败停止，不循环刷新。
5. 用户退出、换账号或换服务器时 generation 增加；旧请求/刷新结果不得覆盖新账号。
6. 刷新网络失败保留旧持久凭证并显示暂不可用；明确撤销则清除当前会话。
7. 对刷新已完成但响应丢失且服务器随后重启的边界，遵循后端明确错误并要求重新认证，不宣称无条件恢复。

退出先取消当前账号任务并清理本地凭证，远端注销失败时提示“本机已退出，远端未确认”，不阻止本地退出。下次账号恢复不能重放已退出账号的待发送请求。

## 5. 网络请求和来源边界

- 普通 API 默认连接超时 10 秒、读取超时 30 秒；正文/搜索/转码按独立请求类别配置，不把全局超时无限放大。
- 幂等读取最多自动重试 2 次，指数退避并带抖动；用户可以手动重试。
- 429 尊重 Retry-After；无可用网络时等待网络恢复，不空转重试。
- POST 登录、创建会话、收藏切换等不做通用自动重试；只允许约定幂等键或目标状态式操作重试。
- 实时事件只在相关前台页面订阅；回前台刷新权威状态，不依赖后台长连接永不掉线。
- API、图片和媒体请求共享来源判断，但不能把 Authorization 设为全局任意 URL 默认头。
- 外站 302 后清除 MeBox 凭证。拒绝未经显式允许的 HTTPS → HTTP 降级；解析重定向不复用外站 Cookie 到 MeBox。
- 日志不输出密码、token、Cookie、PIN、完整签名查询参数；导出诊断需用户操作。

## 6. 原生播放与后台音频

### 6.1 播放控制器

界面只消费 PlayerUiState 并派发用户操作；PlayerController 负责创建/结束会话、Media3 绑定、候选切换、绝对位置转换和资源释放。

播放状态：Preparing、Playing、Paused、Buffering、Recovering、Ended、Failed。每次异步操作绑定播放 generation，旧影片的回调不能污染新影片。

### 6.2 能力与候选

- 设备能力结合 MediaCodec/Media3 探测与实际失败情况，不把扩展名等同可解码。
- 优先直接播放；按后端候选选择重封装、云端 HLS 或本地 HLS。
- 每轮恢复最多刷新同候选一次，然后依次尝试尚未失败的可用候选；全部失败后显示原因与手动重试，不无限往返。
- 服务端返回的 timeline_offset_ms 与播放器相对位置合成绝对 position_ms。
- 更换候选、网络恢复或服务器会话丢失后保留绝对进度；只有用户明确选择从头播放才归零。
- 复杂 ASS 效果、图片字幕、HDR、杜比和多声道按真实样本验证；不能把网页已有能力直接列为原生播放器已支持。

### 6.3 生命周期

首版视频默认退后台暂停；有声书/音频显式进入 MediaSessionService，提供通知栏、锁屏与耳机控制。

- 音频焦点丢失、来电和耳机拔出按规则暂停/降低音量，恢复不违反用户最后一次暂停操作。
- 同一应用视频/音频不同时争抢播放；由一个媒体协调入口转交控制权。
- 旋转/重建通过保留状态与媒体会话恢复，不重复创建转码任务。
- 服务退出、播放结束和用户关闭时释放自己的播放会话；异常回收由服务端租约兜底。
- 进度初始每 5 秒本地保存、每 15 秒在线同步，暂停/切换/退出时增加一次保存；系统强杀只能恢复最后一次已提交位置，不承诺零损失。

## 7. 阅读、漫画、听书与特殊页面

- 服务端继续执行书源规则、Cookie、防盗链、解密和净化；安卓不保存网盘密钥或复制解析引擎。
- 原生正文/批量与私有媒体采用 02 定义的 v1 会话受保护入口；资源过期重取清单，音频分片/图片请求不绕回无时效旧签名路径。书架、搜索等符合要求的元数据仍可复用既有接口。
- 文本按服务端规范正文渲染，存章节身份、段落和字符偏移；字号变化后重新定位。
- 漫画按图片顺序和图内比例恢复，预取窗口与内存有上限，不一次解码全书图片。
- 有声书按章节和毫秒保存，支持倍速、定时关闭和下一章。
- 文本朗读采用 Android TextToSpeech 作为独立可选能力：记录段落/字符进度，支持停止与错误提示；声音包缺失不影响正常阅读。
- 阅读偏好区分服务器同步设置与设备级亮度/布局偏好；不直接将整个本地设置覆盖服务端。
- 特殊 WebView 优先承载现有 MeBox 签名代理页面并接入待办回传；真实外站 Cookie 登录属于另一种方案，未验证前不宣称互通。
- JavaScript 桥只在受控 MeBox 代理页面启用，最小化暴露方法，绑定待办 ID 与当前账号；外部导航禁用桥，不向第三方注入 token。
- 页面取消/超时要回传取消状态并清理桥；服务端待办过期后 App 不继续提交旧 DOM。

## 8. 本地数据和同步

### 8.1 Room 逻辑实体

- ServerConfig：配置 ID、server_id、规范地址、HTTP 风险确认状态。
- AccountScope：server_id、user_id、当前 profile_id 与账号显示信息。
- MediaSummary / BookshelfEntry：分页展示缓存与更新时间；敏感可见性按 profile_id 区分。
- LocalProgress：资源身份、类型化位置、服务端 revision、最后已落盘事件。
- ProgressOutbox：event_id、账号分区、资源、payload、顺序、重试次数、状态与冲突信息。
- CachedChapter / CachedAsset：内容版本、文件路径、校验信息、体积与最后访问时间。

本地库与文件不含明文账号密码。私有正文和媒体清单放应用私有目录，普通 HTTP 缓存不覆盖持久离线缓存责任。

### 8.2 队列语义

先在同一事务更新 LocalProgress 与 outbox，再尝试发送。重复发送保持 event_id 不变；服务端确认后才移除/标记已确认。

高频未发送进度可按同会话顺序合并，只保留最新一次实际用户位置，不能按最大位置合并。认证失效时暂停该账号队列；资源删除时结束任务；冲突保留双方数据并提示处理。

切换账号/服务器后绝不把旧队列换 token 发送到新实例。退出默认删除该账号私有内容；缓存清理不得删除尚未解决的进度冲突证据。

### 8.3 备份与恢复

系统备份排除令牌密文、Keystore 相关状态、私有缓存与待发送认证材料。恢复后检测密钥缺失，清理不可解密会话并要求重新登录，不能进入崩溃循环。

容量设上限，LRU 只淘汰可重建的非固定离线内容。用户明确下载的章节由下载管理控制，不被普通图片缓存自动清理。
