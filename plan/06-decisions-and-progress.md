## 1. 决策状态的含义

- 已确认：用户明确要求或已经验证的工程事实。
- 默认建议：本规划采用的执行默认值，M0 可在有证据或需求变化时调整。
- 待确认：会影响范围/成本的用户或环境信息；必须在相关任务开始前解决。
- 已替代：未来新决策覆盖旧决策，保留历史原因，不能只删除旧记录。

## 2. 已确认事实

- 用户要求为 `D:\project\MeBox` 开发安卓 App，输入后端地址、用户名和密码即可连接使用。
- 用户认为目前网页使用不够稳定；尚未提供具体故障步骤、设备、部署方式和失败日志。
- 用户要求把设计与开发计划保存在当前项目 `plan` 目录，供后续逐步开发。
- 当前 App 项目尚无 Android 工程，只有原始 README 与本次规划文件。
- 现有 MeBox 已有独立 API、双令牌、设备管理、影视和阅读子系统；此次没有修改这些功能。
- 当前规划基于源码静态检查，未运行在线排障、媒体播放或安卓构建。

## 3. 设计决策

### ADR-001 原生安卓路线

状态：默认建议。

选择 Kotlin + Compose + Media3，优先安卓播放、后台音频和生命周期控制。若近期确定要同时交付 iOS，再于创建工程前评估跨平台路线。

变更影响：03 全文、M0-02、M2 与所有客户端任务；不要已有大量 Kotlin 实现后才无记录切换技术。

### ADR-002 保留后端，增量提供移动端契约

状态：默认建议。

保留现有网页/Emby 入口，新增 `/api/v1` 适配而非复制服务层。既有媒体浏览和阅读端点可继续复用，认证/会话/统一播放/阅读锚点使用新协议明确语义。

变更影响：02、OpenAPI、契约测试和 App 网络 DTO 必须一起更新。

### ADR-003 影视优先，阅读可前置

状态：默认建议；主要痛点待确认。

默认顺序 M0→M1→M2→M3→M4→M5→M6。若用户主要使用阅读/听书，M4 可以先于 M3；文本/漫画不依赖视频模块，音频需实现自身媒体服务与资源策略。

M4 内的文本朗读为可选增强，不自动变成首版前置条件。影视离线下载是单独产品范围，不混入章节离线。

### ADR-004 首版连接与系统支持范围

状态：默认建议。

Android 手机/平板、推荐 minSdk 26、单活动服务器、根路径部署。包名暂定 `app.mebox.android`，M0-02 锁定工具链和分发信息。

多服务器 UI、自签名证书实例信任、反代子路径、电视遥控器和 iOS 均需独立任务，不默认为已支持。

### ADR-005 安全认证与撤销

状态：默认建议。

不长期保存密码；令牌由 Keystore 保护。新会话 JWT 包含 sid，对新旧 API 都检查 sid 关联会话。旧无 sid 令牌保留兼容路径，但不能借兼容路径绕过新会话撤销。

临时网络/服务错误保留凭证；明确撤销/到期才重新认证。普通退出先本地生效，远端未确认单独提示。

### ADR-006 播放与转码隔离

状态：默认建议，现有媒体 ID 中心实现已检查。

新协议采用独立播放会话和候选代次，避免同片不同进度互相影响。相同参数作业共享是后续优化，不先牺牲隔离换取缓存命中。

### ADR-007 阅读定位和冲突

状态：默认建议。

文本使用章节身份+段落/字符，漫画使用图片序号+比例，音频使用毫秒。条件更新使用 revision，旧网页进度发生变更也更新 revision。不能用最后请求到达或取最大位置代替冲突策略。

### ADR-008 首版单实例与刷新恢复边界

状态：默认建议；极端恢复需求待确认。

继续支持单实例；不为 App 强制引入 Redis。现有刷新轮换复用结果在内存，响应丢失后再遇服务重启可能需要重新登录。首版对该情况测试并说明；若要求无感恢复则增设持久幂等轮换设计和安全验证。

多副本部署、共享会话与转码路由不在首版承诺内。

## 4. 待确认事项与解除条件

### U-01 实际不稳定表现

需要信息：最常失败的功能、操作步骤、手机/浏览器、局域网或公网、后端部署版本。

解除条件：M0-01 形成可比较记录，确定首个重点业务；没有复现证据时不进行针对假设根因的大型重构。

### U-02 资源与播放能力范围

需要信息：本地/STRM/115/远程 Emby 占比，字幕/多音轨/HEVC 等实际需求，以及合法样本。

解除条件：M0-03 冻结首版支持清单；每项都有后续验证路径。

### U-03 安卓设备与发布方式

需要信息：主要 Android 版本、手机/平板、侧载 APK 或应用商店、签名负责人、包名。

解除条件：M0-02 记录稳定工具链和发布要求；商店政策由实际目标渠道验证，不凭经验宣称符合。

### U-04 网络与证书

需要信息：是否公网 HTTPS、局域网 HTTP、内外网双地址、自签证书、反代子路径。

解除条件：首版范围中明确支持/拒绝行为，超出范围的要求先立项再编码。

## 5. 风险与应对

### RISK-01 App 无法单独解决上游/后端故障

应对：M0 做同资源同网络基线；错误追踪覆盖后端/反代/上游，不只改客户端超时。发布说明不承诺所有网盘/书源稳定。

### RISK-02 多设备转码和候选切换互相影响

应对：M3-03 强制会话隔离和真实并发测试；未通过前不发布依赖新转码的功能。

### RISK-03 多端旧进度覆盖新进度

应对：影视有序事件，阅读 revision 和锚点；旧网页写入也纳入版本变化；离线冲突不静默处理。

### RISK-04 媒体来源和 WebView 泄露认证材料

应对：来源限定网络层、跨站重定向清凭证、受控页面最小桥接、票据最小权限和日志脱敏；安全失败阻断发布。

### RISK-05 原生播放器/书源兼容低于用户预期

应对：按样本公布能力；复杂字幕和特殊书源先做验证，不将网页已有按钮列为 App 已实现能力。

### RISK-06 后端新协议破坏老客户端

应对：兼容入口保留、无 sid 老令牌回归、真实网页/第三方客户端验证、能力开关控制。

### RISK-07 范围扩大导致首版长期无法交付

应对：每阶段独立业务闭环；管理后台、多平台、电视、影视下载和高级效果分开排期；不要求可选功能全部完成才发布已有能力。

### RISK-08 测试环境不足产生虚假通过

应对：明确 Skip/未执行/阻塞；模拟器不等价所有手机；SQLite 不等价 PostgreSQL；编译成功不等价媒体样本可用。
