# 01 总体设计与范围

日期：2026-10-17  
状态：供分阶段实施的设计基线；默认项在 M0 复核。  
关联：[开发计划](04-development-roadmap.md)、[决策记录](06-decisions-and-progress.md)。

## 1. 产品目标

用户在安卓端填写 MeBox 服务器地址、用户名和密码即可使用已有账号与内容。账号、权限、媒体库、书架和权威进度仍由原有 MeBox 管理。

产品质量目标：

1. 临时网络故障不被当成密码失效；重新打开 App 可恢复有效会话。
2. 视频和音频采用可管理生命周期的原生播放方式。
3. 进度先可靠保存到手机，再与服务器同步；不依赖关闭页面时的一次请求。
4. 地址、账号、权限、解码和上游资源错误可以区分、追踪与恢复。
5. 后端升级不破坏已有网页与 Emby/Jellyfin 兼容客户端。

这不是把现有网页整体装进 WebView 的项目，也不是重写 MeBox 服务端。

## 2. 已检查到的工程事实

检查方式为源码静态阅读，未连接实际部署实例，未复现用户故障。

### 2.1 后端与网页

- 后端采用 Go、Gin、GORM，支持 SQLite / PostgreSQL，可选 Redis / OpenSearch。
- 网页采用 React、TypeScript、Vite、Zustand，已有独立 `/api` 接口。
- 认证已有访问令牌、刷新令牌轮换、部分并发刷新保护与设备管理。
- 现有版本接口将版本固定为 `0.1.0`，需要真实构建版本与 API 兼容信息。
- 普通登录的客户端记录目前写为 Web；刷新令牌模型尚无设备会话关联字段。
- 影视已有直连、本地 HLS 转码、115 播放、远程 Emby、字幕、收藏和进度。
- 本地转码任务、目录和停止操作以媒体 ID 为中心；需要验证并补齐播放会话隔离。
- 影视进度已有 session_id、session_started_at_ms、sequence 防乱序能力；不能将其描述成完全没有进度保护。
- 阅读已有按用户书架、搜索、目录、正文、漫画/音频代理、阅读偏好和批量正文接口。
- 阅读位置字段兼容页码、图片序号和音频秒数，尚不足以直接表达稳定的跨设备文本锚点。
- 现有阅读媒体 HMAC 签名不包含有效期；不能当作已经具备短期资源票据。
- 刷新轮换的复用记录与部分运行会话位于进程内；单实例重启和多副本是需要分别验证的场景。

### 2.2 安卓项目

当前项目只有 README，尚无 Gradle 工程、Android 应用、客户端源码或自动化测试。

后续文档中列出的 Android 文件均属于拟新增内容。

## 3. 为什么需要同时调整后端和 App

原生 App 能更直接地管理音视频、后台音频、持久缓存、网络状态和本地进度，但无法单独修复后端数据库错误、反代超时、网盘换链或书源站点故障。

M0 将问题按五层记录：

1. 客户端：生命周期、解码、缓存和并发请求。
2. 接入网络：域名解析、TLS、局域网/公网、网络切换。
3. 反向代理：Range、流式缓冲、升级连接和超时。
4. MeBox：认证、授权、进度、转码和数据库。
5. 上游资源：网盘、远程 Emby、书源站点及其限流。

这些是排查分类，不是已经确定的故障原因。每条故障至少关联操作步骤、时间、客户端/服务版本、网络、资源类型和脱敏请求 ID。

## 4. 技术路线比较与选择

### 4.1 默认：原生 Android

采用 Kotlin + Jetpack Compose + Media3。

收益：生命周期、音频焦点、通知栏、耳机控制、画中画和后台媒体服务都有直接集成路径。适合当前安卓稳定使用的目标。

成本：界面需要新写；iOS 将来需另外规划；视频、音轨和高级字幕能力仍取决于设备与实现，不能承诺所有格式直接播放。

### 4.2 备选：跨平台

Flutter / React Native 适合短期确定需要同时维护 Android 与 iOS 的情况。媒体、后台服务、下载和特殊 WebView 仍需平台适配，不以“代码共用”推断稳定性自然成立。

若切换该路线，应在 M0 更新 ADR-001，并重新确认播放器、存储和后台生命周期设计，再建立工程。

### 4.3 过渡：网页封装

WebView / Capacitor 可快速验证账号接入和内容浏览，但会继承网页播放和浏览器运行限制。本项目不将其作为主界面技术；只允许特殊站点登录等受控页面局部使用。

## 5. 系统职责边界

### 安卓端

- 连接配置与服务器身份确认。
- 账号会话、安全凭证存储和原生设备标识。
- 媒体、书架、搜索和详情展示。
- 视频、音频和原生阅读呈现。
- 本地缓存、待同步任务、网络恢复和脱敏诊断。

### MeBox 后端

- 账号、权限、播放配置和设备会话校验。
- 媒体与阅读数据的权威存储。
- 网盘授权、直链解析、资源代理、转码与上游接入。
- 书源规则执行、登录状态和内容处理。
- 播放能力协商、会话生命周期与进度一致性。

### 现有网页与第三方客户端

网页继续承担管理后台和已有使用入口。Emby/Jellyfin 兼容层保持独立协议入口，但复用既有业务服务，不为安卓新建另一套媒体数据库或书源解析逻辑。

## 6. 首版范围与后续范围

### 首个业务版本包含

- 单活动服务器、地址测试、账号登录、凭证恢复、退出与设备识别。
- 权限和播放配置/PIN 适配，不能绕过服务器限制。
- 一个业务闭环；默认影视：媒体库、搜索、详情、选集、原生播放、字幕/音轨、收藏、历史、续播。
- 进度本地保底、可重试同步和基础诊断。
- 普通账号使用；管理员可正常登录，但管理功能主要留在网页。

### 后续独立交付

- 阅读、漫画、后台听书与文本朗读。
- 章节离线缓存、容量管理和增量同步。
- 多服务器配置切换、内外网地址绑定。
- 画中画、弹幕、高级字幕效果、投屏等增强功能。
- 影视离线下载：需单独确认资源授权、链接刷新、Range、HLS 下载、容量和失败恢复。

### 首版不包含

- Android TV / 遥控器导航、iOS、云中转服务或厂商推送平台。
- 在手机上复制完整文件管理、刮削、网盘授权与系统运维后台。
- 在 App 里重新实现完整书源规则引擎。
- 为开发 App 强制重构成微服务、引入消息队列或替换数据库。

## 7. 关键数据流

### 登录

地址规范化 → 最小服务器信息 → 兼容校验 → 设备会话登录 → 凭证原子加密保存 → 用户权限/播放配置 → 首页。

连接测试失败不发送密码。登录重试遇到不明确响应时，先区分网络失败与服务端拒绝。

### 视频

详情 → 选择播放配置与媒体版本 → 上报设备能力 → 创建播放会话 → 获取候选 → Media3 播放 → 周期性本地保存与有序上报 → 结束自己的会话。

候选失败时有限次恢复；仅在后端提供支持的情况下转入其他播放方式。远程 Emby 没有本地原文件时不能假定可以本地转码。

### 阅读与听书

书架 → 章节清单与内容版本 → 服务端正文/资源 → 原生呈现 → 保存类型化位置 → 同步。

特殊登录、验证码和段评按服务端待办协议打开隔离 WebView；取消与超时必须释放等待。外站页面不获得 MeBox 登录令牌。

## 8. 稳定性和安全原则

- 账号密码只用于认证请求；默认不长期保存密码。
- 本地数据按 server_id + user_id 分区；受播放配置权限影响的缓存还需按 profile_id 区分。
- 公网默认 HTTPS；局域网 HTTP 必须显式确认，不能通过静默降级规避 TLS 错误。
- 初期只信任系统 TLS 证书链；自签名证书的导入/实例信任为后续独立项。
- MeBox Authorization 不转发给跨来源重定向目标。
- 并发认证失败只触发一次凭证刷新，重放上限明确，禁止无限循环。
- 同一条写入事件使用稳定 ID；收藏设置为目标状态，不对“切换收藏”接口盲目重试。
- 已完成章节的离线可用与在线授权撤销分别定义，退出账号默认清除该账号私有缓存。
- 不将 WorkManager 当持续播放器或实时长连接守护进程。

## 9. 实施依赖与设计变更

M0 先完成故障基线、工具链和首模块确认；M1 提供接入契约；M2 完成安卓接入。M3 和 M4 复用 M2，但各自的服务端契约必须先通过测试。M5 建立在对应业务版本可用之后，M6 是发布质量门槛。

开始一项任务前，可将该任务进一步拆成小型测试驱动提交，但不提前承诺未来全部模块的固定类实现。接口字段变化以 02 的冻结契约和 OpenAPI 为准；Android 结构以 03 为准；实际任务进度仅在 04 更新。
