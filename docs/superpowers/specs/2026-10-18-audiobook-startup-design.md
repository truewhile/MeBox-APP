# 听书起播与加载反馈优化

用户已于 2026-10-18 确认：同时优化起播链路和加载反馈，沿用现有播放页布局。

## 问题与范围

- `ReaderAudioEngine.loadChapter` 在 `prepare()` 后立即清除 loading、把 autoplay 当成 playing，导致缓冲期间显示失真。
- 加载期间的播放/暂停意图与装载时的 autoplay 分离，点击可能失效；失败后再次播放可能使用旧章或失败的媒体项目。
- 后台听书服务使用默认数据源，没有复用应用现有 OkHttp 连接池。
- 异步控制器连接仅按章号判断旧结果，同章重试、换书、停止后的过期回调可能覆盖新请求。

## 设计

1. 提取不依赖 Android 的播放请求状态，维护请求编号、音轨准备阶段、缓冲状态、真实播放状态和最新播放意图。准备与缓冲连续展示 loading；只有播放器事件可以确认真正播放。
2. 加载期间点击播放/暂停只更新意图，不重启章节请求。换章/停止使旧请求失效。停止旧音轨并暂停进度轮询，避免把旧音轨位置写入新章。
3. 加载或播放失败后点击播放重新获取本章音轨，从已记录的位置重试。服务连接失败清理等待回调并允许重连。
4. 播放页保留原布局，播放按钮用明显的中心加载指示和播放意图图标；底部区分准备、缓冲、播放、暂停、失败重试。章节内容请求阶段也显示反馈，合并重复点击。
5. 后台服务的 HTTP 数据源复用应用 OkHttp 的连接池及 DNS；关闭 HTTP 磁盘缓存，避免音频污染接口缓存。将首次播放缓冲阈值设为 750ms，重新缓冲阈值为 2000ms，保留 50 秒的后台缓冲窗口。
6. 记录准备音轨、装载媒体和实际开始播放的耗时；只记录书籍 ID 与章号，不记录签名音轨 URL。

## 验证

- 状态单测覆盖：准备期间收到旧播放器事件、装载后继续缓冲、真正起播、加载中暂停/恢复、失败重试、同章重试/换书/停止使旧回调失效。
- HTTP 单测使用本地 MockWebServer 验证连接复用及关闭磁盘缓存。
- 执行 `:app:testDebugUnitTest`、`:app:lintDebug` 和 `:app:assembleDebug`。
- 无真机与真实书源时，只报告已通过的自动验证，不声称实际起播耗时已经测得或所有设备已验证。

## 非目标

不改服务端接口，不增加整章预下载或自动多章预取，不修改影视播放器，不更换播放页视觉设计。
