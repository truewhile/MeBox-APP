# 阅读可靠性与离线入口设计

日期：2026-10-20
依据：用户已要求实施上一轮功能优化建议；本批实现第一阶段，后续阶段保持独立验收。

## 分批范围

1. 本批：文本/漫画本地检查点、持久待同步进度、串行重试；章节缓存完整性、取消/失败重试；受限离线书架。
2. 下一批：影视跨设备续播冲突选择、观影档案/PIN、影视片段跳过。续播接口当前 DTO 没有版本时间，不能用客户端时间臆测跨设备新旧。
3. 后续：TXT/EPUB 导入、净化规则、资料与设备管理；文本翻页/漫画增强、播放列表/媒体库偏好；统计、外部播放器、多服务器、TTS、书签。
4. 单独立项：DLNA、影视离线、HLS 音轨离线。完整管理后台继续留在网页。

## 进度

- 延用既有页码/图片序号契约，不承诺稳定段落锚点。
- 新建 ReaderProgressStore，按服务器、用户、书籍隔离，保存章节、位置、更新时间、章节 URL 和待同步标志。逐次落盘，不依赖退出请求。
- 每本书只保留最新事件；串行发送，旧请求的成功回执只能确认同一事件，不能清除新位置。
- 仅在本地比服务器更新且目录定位有效时恢复本地，支持主动向后阅读。目录 URL 不匹配时尝试按 URL 定位，找不到则使用服务端位置。
- 在初始化、刷新书架、阅读防抖和在线定时重试时补传；离线模式从不发送请求。网络失败、取消、认证失效都保留待同步记录；明确提示本机已保存、等待同步。
- 上传前读取服务端书架，服务端进度时间更新时放弃旧本地待同步事件，避免恢复网络后覆盖另一设备更晚阅读。既有接口无原子版本条件，仍不能消除读取和写入之间的跨设备竞争。

## 缓存

- 章节 JSON 存在不代表完整。text 有正文才完整；image/audio 的全部资源必须是私有缓存目录内实际存在且非空的文件；HLS 不支持完整离线。
- 完整、部分、未缓存分开。旧章节记录也按实际文件检查，不以新元数据迁移为前提。
- 提供缓存任务取消、仅失败章节重试；下载成功数仅计完整章节。取消传播到 HTTP Call，并清理临时文件；已成功资源保留用于重试。
- 写入使用唯一临时文件和原子替换，避免自动缓存与手动缓存争用固定临时名；路径保留兼容已有目录，但拒绝 . 和 .. 路径。
- 缓存按账号和书籍维护内存代次：清理账号/书籍时提升代次并取消在途 HTTP；缓存任务携带启动时的代次，代次不符即停止，迟到的下载结果不能再把已清理的文件写回。代次只存在于进程内，重启后按磁盘实际文件重新判定。
- 本批仍是界面生命周期内的下载任务，不承诺系统终止后后台续传、仅 Wi-Fi 或容量配额。

## 离线入口

- 连接/恢复会话页可直接进入本机上次账号的缓存书架，不等待网络；按钮只在本机有账号、凭证和已确认服务器快照时可用。
- 新增独立 Offline 状态，不伪造 Account，也不授予媒体库、账号管理、搜索、书源、上传和网络同步权限。
- 阅读界面复用 ReaderViewModel 的 offlineOnly 模式，目录和正文只读缓存；不下载网络封面，不启动音频（音频后台自动切章单独适配后开放）。
- 离线书架只展示有完整缓存章节的文本/漫画书籍；未缓存章节明确报错。退出离线返回连接恢复，不自动变成在线账号。
- 主动退出账号和删除书籍清除相应本地检查点；已有听书独立检查点保持原流程。
- 离线入口的可用性检查与工厂构建都在 IO 上完成，组合期间不读取凭证、快照或磁盘；阅读 ViewModel 的键跟随会话与进度代次，避免 Activity 级 ViewModel 复用已撤销的会话。

## 验收

- JVM 测试覆盖：进度落盘重建、账号隔离、回退阅读、旧回执不清新事件、服务端更新不被旧离线覆盖、目录变化；缓存部分失败/资源缺失/HLS/空正文、失败资源重试、取消临时文件清理和完整索引。
- 离线仓库读取在网络请求之前返回，网络接口请求数为零；只允许阅读缓存文本/漫画。
- 全量单元测试、assembleDebug、lintDebug；真机、断网 UI 和后台杀进程若未实际执行必须单列未验证。
